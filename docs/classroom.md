# 教師分享與公共 PeerJS 教室

教室使用 PeerJS 1.5.5 的公共 PeerServer Cloud；建立 `new Peer({ secure: true })`，不指定舊主機、連接埠、key 或自訂 ID，讓套件使用 TLS 443 與預設 ICE 設定，由公共服務分配隨機 ID。[PeerJS 官方公共服務說明](https://peerjs.com/server/cloud)、[Peer API](https://peerjs.com/client/api/peer)。

## 教師與學生流程

1. 教師按上方工具列「教室」（或選單「一起學習」）開啟「教室與分享」Modal，再按「建立教室」。目前頁面與編輯內容保留，不會切到獨立教室頁。
2. 分享 Modal 中的 QR Code、按「下載 QR Code」，或按「複製教室連結」。QR Code 在本機瀏覽器產生，內容就是同一個分享 URL，不呼叫外部 QR 服務。剪貼簿權限不允許時，可選取唯讀連結欄位手動複製。按「開始上課」會關閉設定、進入編輯器並開啟教室通訊。
3. 學生掃碼或開啟分享連結，預設顯示全畫面的「加入老師的教室」Modal，老師 ID 已帶入，焦點在暱稱欄位。填暱稱後按 Enter 或「加入教室」；成功連線才自動關閉 Modal，直接顯示編輯器與教室通訊。不會因開啟 URL 就自動連線、傳送程式或開啟麥克風。
4. 連線後，右下角「教室通訊」在編輯器、範例、AI 與 Console 都可使用。它不鎖住編輯區；收合後仍有未讀數量及短暫通知，收到訊息不切換頁面或搶走編輯焦點。
5. 老師在「訊息」輸入文字並按「廣播訊息」，會傳給當下已連線的全部同學；也可「廣播目前程式」。同學的文字訊息只傳給老師，其他同學不會收到。Ctrl／⌘ Enter 可送出文字，不會執行編輯器程式。
6. 同學在「送交程式」填寫選填問題，按「送交目前程式給老師」。送交包含當時的檔名、完整程式與問題；之後繼續編輯不會改變這份快照。「老師端已收到」代表接收端已確認收件，不代表老師已閱讀或檢查。可用「查看送交版本」比對。
7. 老師從通知或「收到的程式」開啟「檢查程式」，閱讀全文與問題、選擇「檢查語法」，再輸入意見並「送出檢查回覆」。語法檢查只解析 Python，不執行程式，也不代表邏輯正確。回覆只送到原送交者的資料連線；學生會看到「老師已回覆檢查意見」。對方離線時會明確提示未送出並保留視窗內草稿。
8. 收到老師或學生的程式，可預覽、「另存並開啟」或略過。另存使用新檔名，不覆寫原檔，不自動執行。切換頁面或另存檔案仍保持原教室與分享連結。按「結束連線」或關閉／重整分頁才結束該端工作階段。

分享 URL 保留網站路徑前綴，僅帶 `?peer=教室ID#/`，不複製教師網址上的其他 query 參數。連結是暫時工作階段的邀請：教師關閉分頁或重新建立教室後，應分享新連結。沒有登入驗證、永久教室或課堂資料庫。舊 `#/classroom` 入口仍可開啟設定 Modal，背景為編輯器，網址會正規化成 `#/`。關閉設定不會斷線；可隨時由上方教室按鈕或通訊面板的「教室與分享設定」重開。加入成功或關閉邀請時會移除網址的 `peer` 參數；重整後需再使用老師的分享連結加入。

## 即時語音

連線後在右下角「教室通訊 → 語音」操作，老師與同學都可以即時開麥：

- 老師按「開啟麥克風廣播」，聲音傳給當下已連線的全部同學；老師開麥期間，晚加入或重新加入的同學也會建立語音連線。
- 同學按「開啟麥克風傳給老師」，聲音只送給老師。不同同學的聲音不會轉送到其他同學。老師與同學可同時開麥，老師可同時接收多位同學。
- 收聽端先按「啟用語音收聽」，不需授權或開啟自己的麥克風。可暫停收聽、調音量；瀏覽器阻擋播放時，會顯示「點此播放語音」供手動啟動。
- 按開麥才呼叫瀏覽器麥克風權限。等待權限時可取消；即使稍後才按允許，已取消或離開教室的請求也不會留下啟用的麥克風。
- 「暫時靜音麥克風」停送聲音、保留裝置與連線；「關閉麥克風」停止音軌並釋放裝置。收合通訊面板仍有麥克風狀態與關閉按鈕，切到編輯器、範例、AI 或 Console 不會結束語音。離開教室會關閉自己的麥克風及收到的語音。
- 權限拒絕、裝置拔除、播放阻擋及語音連線逾時各有提示。語音失敗不應關閉既有文字／程式資料連線，可明確重試語音。

語音使用同一個公共 PeerJS peer 的 `call()`／`MediaConnection`，每個方向建立獨立的單向音訊連線，接收端使用 `answer()`，不附自己的音軌。只接受同一教室中已有資料連線對象的指定語音協定；未知來源、其他類型與已取消的呼叫會拒絕。`voice-stop` 控制封包依來源及呼叫 ID 關閉對應語音，避免停止／重開與訊號交換的先後順序留下舊播放器。這不是登入身分驗證。

麥克風需要安全來源（正式站使用 HTTPS；本機開發可用 localhost）。這與 AI 自訂端點允許 HTTP 的設定不同，屬於瀏覽器的媒體權限要求。語音不錄音、不存進本機檔案或對話紀錄。建議使用耳機以減少回音。每位同學各有獨立連線，老師上傳與處理負載會隨人數增加；本次驗證沒有宣稱大型班級的容量或所有校園網路都能連通。

依據：[PeerJS 音訊與單向通話](https://peerjs.com/client/getting-started#videoaudio-calls)、[MediaConnection](https://peerjs.com/client/api/media-connection)、[瀏覽器麥克風權限](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[自動播放限制](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。

## 斷線與資料處理

- 訊號服務斷線時停用複製分享按鈕並提示「重新連接服務」；既有 WebRTC 資料連線可繼續使用。重連成功保留原 ID，不會重複建立學生資料通道。
- 單一學生關閉或傳輸錯誤時，只移除該學生；其他人及教師教室持續運作。學生失去教師資料連線時，提示使用最新連結重新加入。
- 過期／不存在的教師 ID 會顯示可操作的錯誤；初次連線與訊號重連最長等待 20 秒，逾時可重新建立或加入。
- 收件匣與自己的送交紀錄各保留最近 20 份；正在檢查的收件不會因新程式到來被擠掉。每份程式上限 1,000,000 字元；訊息、問題及檢查意見各上限 2,000 字元。訊息紀錄保留最近 100 筆。這些資料只在本分頁記憶體中，重整會清除；重要程式請另存或下載。斷線後仍能閱讀、另存已收到的程式。
- 傳輸協定保留教師的 `{type:"teacherInfo",code}` 與學生的 `{type:"code",code}`，新版本增加 `id`、`filename`、`question`，另有 `message`、`receipt`、`feedback`。舊程式封包仍可接收；收件確認與檢查回覆需雙方使用新版本。只接受符合角色與長度限制的封包，依連線來源及封包 ID 去重；不同學生相同 ID 不會混淆檢查對象。遠端暱稱只作為最多 40 字元的純文字顯示，不信任 metadata 的身份宣稱。
- 程式透過 WebRTC 資料通道交換；公共 PeerJS 服務負責訊號交換。暱稱也會出現在連線 metadata，請使用不含個資的暱稱。公共服務、學校防火牆、NAT 及 TURN/STUN 可用性仍可能影響跨網路連線，單次成功不保證所有校園環境都可連線。[PeerJS FAQ](https://peerjs.com/client/faq)。

## 驗證（2026-10-27）

新增 3 項 Modal 流程測試，實際將 QR 圖轉成像素並用獨立解碼器確認等於分享 URL；涵蓋全畫面暱稱表單、Enter 加入後直接編輯與通訊、原檔保留、舊網址、手機與無障礙。

CI 使用模擬傳輸，涵蓋分享 URL、剪貼簿、學生 ID 預填、編輯後保留教室、單一同學斷線、訊號重連不重複通道、過期 ID、逾時、收件匣限制與來源、手機版和無障礙檢查，避免 CI 依賴公共服務的即時狀態。

另外以三個隔離的 headless Chromium 瀏覽器（老師與兩位同學），使用測試代號與合成程式實測公共 `wss://0.peerjs.com`：教師在 Modal 建立與複製連結、解碼 QR Code、兩位同學由分享連結的全畫面表單加入並自動開啟通訊、編輯器內廣播給兩人、學生送交快照與收件確認、老師全文預覽與不執行的語法檢查、只給送交者的回覆、老師廣播程式與另存，以及學生退出後教師仍保持原分享連結。編輯中與接收程式後，雙方原檔均保持完整。沒有傳送真實學生資料。驗證報告與截圖放在忽略的 `artifacts/`；發布後也會針對正式網站重跑此流程。

可重跑的公共服務驗收（預設 CI 不會執行）：

```sh
# 先在另一個終端機啟動 npm run preview -- --port 4173
npm run test:classroom:public

# 或驗證正式站；三個瀏覽器均使用全新的隔離工作區
CLASSROOM_VERIFY_URL=https://boyofunpython.github.io/ npm run test:classroom:public
```

此命令會建立短暫的公共 PeerJS 測試連線、傳送合成程式並在結束時關閉，不接觸使用者的瀏覽器資料或系統剪貼簿。

語音驗收使用 Chromium 的假麥克風裝置與產生的純音 WAV，不使用操作電腦的真實麥克風。PeerJS 與 WebRTC 沒有 mock；檢查雙向 RTP 封包、接收端非零解碼音訊能量及播放器進度，並確認學生音訊沒有送給其他學生、靜音／釋放音軌、晚加入與跨頁面連續收聽。接著仍會執行原有文字、送交程式與私人回覆驗收。

```sh
npm run test:classroom:voice:public
CLASSROOM_VERIFY_URL=https://boyofunpython.github.io/ npm run test:classroom:voice:public
```

報告為 `artifacts/classroom-voice-public-verification.json`。這是隔離 Chromium 環境的傳輸與播放證據；未包含人耳聽感、實際設備回音、Safari／Firefox 或跨校網路的驗證。
